# «Питание» — дизайн

Дата: 2026-10-23 · Статус: дизайн согласован в чате (варианты, часть 1, часть 2); спецификация ждёт ревью пользователя.
Макет: `.design/nutrition.webp` (локально, не в репозитории).

## 1. Цель
Вести питание за день так же просто, как тренировку: сфотографировал тарелку → проверил граммы → сохранил. Видеть, сколько съедено калорий и БЖУ относительно дневной нормы.

Критерии успеха:
- Фото блюда → список продуктов с граммами и КБЖУ за ≤ 10 с; правка граммов сразу пересчитывает калории.
- Штрихкод упаковки → продукт из Open Food Facts; ввод граммов → запись.
- Экран «Питание» 1:1 с макетом (сетка 1rem = 1/94.1 ширины, цвета и элементы как на остальных экранах).
- Работает без сети для просмотра и ручного ввода; фото и поиск требуют сети.

Не входит: рецепты и составные блюда-шаблоны, вода, микроэлементы, синхронизация питания с «Здоровьем», справочник USDA (возможен позже как уточнение).

## 2. Решения
| Вопрос | Решение |
|---|---|
| Главный путь ввода | фото блюда; запуск — жёлтый «+» у приёма пищи |
| Второй путь | сканер штрихкода + Open Food Facts; поиск продуктов; ручной ввод |
| Распознавание | модель возвращает продукты, граммы и КБЖУ на 100 г; итог считает приложение |
| Модель | `gpt-6.1-sol` по умолчанию, меняется переменной `OPENAI_MODEL` |
| Ключ OpenAI | только в `/opt/artifex-fit-push/.env` на VPS; кладёт пользователь сам |
| Единицы | граммы; БЖУ в граммах; ккал |
| Норма | расчёт по профилю (Миффлин — Сан Жеор) + ручная правка |
| Хранение | IndexedDB на телефоне; фото не хранятся на сервере |

## 3. Экран (по макету)
- Шапка: «Питание», «Сегодня ▾» (выбор дня: сегодня / вчера / дата), «…» (норма, настройки питания).
- Сводка: кольцо «съедено из нормы ккал», полосы Белки / Жиры / Углеводы «x / y г», четыре плитки (ккал, Б, Ж, У).
- Приёмы пищи: Завтрак, Обед, Ужин, Перекусы — иконка, сумма «ккал · Б · Ж · У», жёлтый «+», раскрытие ˅/˄. В раскрытом — строки продуктов: миниатюра (фото блюда / картинка из OFF / иконка), название, «ккал · Б · Ж · У», «…» (изменить граммы, удалить).
- Нижняя панель действий: Поиск продуктов · Сканировать · Добавить вручную · История.
- «+» у приёма → камера (снимок или галерея: `<input type="file" accept="image/*" capture="environment">`) → необязательная подсказка текстом → распознавание → экран проверки → «Сохранить в <приём>».
- Экран проверки: фото сверху; строки «название · граммы (стрелки ±10 г, ввод) · ккал · Б/Ж/У»; удалить строку; «+ продукт» (поиск/ручной); итог; «Сохранить».
- Приём по умолчанию для нижней панели — по времени: < 11:00 завтрак, < 16:00 обед, < 21:00 ужин, иначе перекус; меняется в форме.
- «История»: список прошлых дней с итогами ккал; тап — открыть день.

## 4. Данные (Dexie, версия схемы 2)
```
foods:   ++id, source('ai'|'off'|'manual'), name, brand?, barcode?, per100 {kcal,p,f,c}, image?, lastUsedAt, &barcode
entries: ++id, date('YYYY-MM-DD'), meal('breakfast'|'lunch'|'dinner'|'snack'), name, grams, kcal, p, f, c, foodId?, photoId?, createdAt   индексы: date
photos:  ++id, blob (JPEG ~512 px), createdAt
settings: 'nutritionTargets' = { kcal, p, f, c, manual: boolean }
```
- КБЖУ записи — снимок на момент сохранения: `kcal = per100.kcal × grams / 100` (аналогично Б/Ж/У), округление до 1 (ккал) и 0,1 (г).
- Экспорт/импорт JSON включает foods и entries (без photos).

## 5. Сервер (`server/`, контейнер `artifex-fit-push`)
- `POST /api/food/photo` `{ deviceId, image: 'data:image/jpeg;base64,…', hint?: string ≤ 200 }` → `{ items: [{ name, grams, per100: {kcal,p,f,c}, confidence }], dish?: string }`.
  - Телефон уменьшает фото до 1024 px по длинной стороне, JPEG 0,8 (≈ 200 КБ). Лимит тела для этого маршрута — 4 МБ.
  - Вызов OpenAI (Responses API), фото + инструкция на русском: перечислить отдельные продукты на тарелке, вес каждого в граммах, КБЖУ на 100 г по стандартным таблицам, уверенность 0–1; названия по-русски. Строгая схема ответа (JSON Schema), если модель поддерживает; иначе — разбор JSON с проверкой.
  - Проверка: 1–15 позиций; граммы 1–2000; ккал/100 г 0–900; Б/Ж/У/100 г 0–100; Б×4+Ж×9+У×4 не больше ккал/100 г × 1,3 (иначе ккал пересчитываются из БЖУ).
  - Лимиты: deviceId формата UUID; ≤ 60 фото на устройство в сутки; ≤ 300 в сутки всего; таймаут OpenAI 30 с.
  - Журнал: время, deviceId (8 символов), модель, токены, длительность, число позиций. Фото не сохраняется.
  - Ошибки — текстом по-русски: нет ключа, лимит, таймаут, модель не вернула JSON.
- `GET /api/food/barcode/:code` → `{ name, brand, per100, image }` или 404; источник `world.openfoodfacts.org/api/v2/product/{code}` c полями `product_name, brands, nutriments, image_front_small_url`, User-Agent `ArtifexFit/1.0 (fit.artifex.mobi)`; кэш на диске.
- `GET /api/food/search?q=` → до 20 продуктов OFF; кэш 24 ч.
- Переменные `.env`: `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-6.1-sol`.

## 6. Сканер
`barcode-detector` (ponyfill на zxing-wasm, MIT/Apache-2.0), загружается при первом открытии сканера; задняя камера (`getUserMedia({ video: { facingMode: 'environment' } })`), форматы EAN-13, EAN-8, UPC-A, UPC-E; распознанный код → `/api/food/barcode/:code` → форма граммов; нет в базе → ручной ввод с этим штрихкодом.

## 7. Норма
- BMR (мужчина) = 10 × кг + 6,25 × см − 5 × возраст + 5; TDEE = BMR × 1,55.
- Цель: набор +10 %, снижение −20 %, поддержание 0 %; округление до 10 ккал.
- Белок = 1 г × вес в lb; жир = 25 % ккал / 9; углеводы = остаток / 4.
- Вес — последний замер из Zepp Life; возраст и рост — из профиля. Нет данных → карточка «Заполни профиль» и ручной ввод нормы.
- Ручная норма (`manual: true`) не пересчитывается автоматически.

## 8. Ошибки
- Нет сети / сервер или OpenAI недоступны → «Не удалось распознать — добавь вручную или попробуй позже»; фото не теряется до закрытия экрана проверки.
- Пустой ответ модели → пустой список с кнопкой «Добавить вручную».
- Камера запрещена → подсказка, как разрешить в Настройках iPhone; выбор из галереи остаётся.

## 9. Тесты
- Клиент (Vitest): норма; итоги дня/приёма; пересчёт граммов; приём по времени; разбор ответа сервера; схема Dexie v2 (миграция с v1 без потерь).
- Сервер (`node --test`): `/api/food/photo` с подменённым OpenAI (валидный ответ, мусор, превышение лимитов, без ключа, проверка БЖУ/ккал); разбор OFF; кэш.
- Ручная проверка: 5 реальных фото блюд после установки ключа; сканирование 3 упаковок.
