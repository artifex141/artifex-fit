# Artifex Fit — MVP: дизайн

Дата: 2026-10-23 · Статус: утверждён (пользователь разрешил писать спецификацию и план без отдельного ревью)

## 1. Цель

Личное приложение для тренировок по программе «Тяжёлые тренировки: 4 недели + разгрузка» (исходник — `docs/program-source.txt`).
Главная ценность: открыть приложение в зале и сразу видеть, что делать сегодня — упражнения, подходы, **уже посчитанные веса** — и записывать факт по подходам с таймером отдыха.

Пользователь: один человек, iPhone + Windows, без Mac и без аккаунта Apple Developer.

### Критерии успеха MVP
- Открывается на iPhone как PWA (с экрана «Домой»), работает без интернета.
- Показывает следующую тренировку по порядку (стартовая позиция — день 12: неделя 2, тренировка «С»).
- Вес каждого рабочего подхода посчитан по правилам программы (или явно помечен «введи вес», если не хватает данных).
- Каждый подход сохраняется сразу после галочки; таймер отдыха стартует автоматически.
- Экран «Прогресс» показывает итоги и график веса по упражнению.
- Данные можно выгрузить и загрузить JSON-файлом.

### Не входит в MVP
Apple Watch/HealthKit (пульс, сон, восстановление), вес тела и состав тела, 3D-фигура, достижения, питание (вкладка-заглушка), редактор программ, облачная синхронизация, push-уведомления при заблокированном экране.

## 2. Решения, принятые с пользователем

| Вопрос | Решение |
|---|---|
| Платформа | PWA (веб) |
| Хранение | локально на телефоне (IndexedDB) + экспорт/импорт JSON |
| Единицы | фунты (lb) |
| Программа | зашита как данные, без редактора |
| Порядок тренировок | по порядку дней программы, не по календарю |
| Вес Н1 при разных весах в подходах | вес большинства подходов (мода; при равенстве — больший) |
| Правило «на 2+ повт. меньше» | применяется автоматически, с подсказкой и возможностью поправить |
| Следующий цикл | спросить пользователя в конце цикла |
| Округление | гантели — шаг 2,5 lb, остальное — 5 lb |
| Запись подхода | по макету: вес + повторы (+ повторы дропа, если есть дропсет) |
| Таймер | автостарт 2:00 после рабочего, 1:00 после разминочного; без фоновых уведомлений |
| Картинки | 18 от пользователя + free-exercise-db (Unlicense) для остальных |
| Хостинг | публичный репозиторий `artifex141/artifex-fit`, GitHub Pages |

## 3. Архитектура

Стек: **Vite + React 18 + TypeScript**, **Dexie** (IndexedDB), **vite-plugin-pwa** (service worker, манифест), **Vitest** (тесты), графики — лёгкий собственный SVG (без библиотеки; одна линия и подписи — библиотека не нужна).

```
src/
  program/            — чистый TS, без React и без БД
    types.ts          — типы программы и журнала
    exercises.ts      — справочник 34 упражнений (id, название, мышцы, оборудование, шаг веса, картинка)
    program.ts        — 3 шаблона дней × 5 недель предписаний
    schedule.ts       — день программы ↔ неделя/тип дня, «следующая тренировка»
    weights.ts        — расчёт целевого веса: якоря Н1/Н3/Н4, правило недобора, округление
    cycle.ts          — переход на новый цикл (варианты «как в программе» / «лучшие результаты»)
  db/
    db.ts             — схема Dexie
    repo.ts           — чтение/запись тренировок и подходов, экспорт/импорт
  ui/
    App.tsx, TabBar.tsx
    workout/          — экран «Тренировка»: WorkoutScreen, ExerciseCard, SetRow, RestTimer, StopWatch
    progress/         — ProgressScreen, LineChart
    profile/          — ProfileScreen, StartWeights, Backup
    nutrition/        — заглушка
  styles/             — токены темы (тёмная, акцент #FFD60A), общие стили
public/exercises/     — картинки упражнений
```

Принцип: вся логика программы — чистые функции в `src/program/`, которые принимают данные журнала как аргумент. Их можно перенести на другую платформу и они покрыты тестами.

## 4. Модель программы

```ts
type WeightRule =
  | { kind: 'fixed'; lb: number }                       // 65 lb
  | { kind: 'added'; lb: number }                       // подтягивания +10 lb (0 = без веса)
  | { kind: 'plates'; perSide: number[] }               // жим ногами: [45,45,20] на сторону
  | { kind: 'pick' }                                    // «подбери вес» (неделя 1)
  | { kind: 'anchor'; week: 1 | 3; deltaLb: number }    // «вес Н1 +5 lb», «вес Н3»
  | { kind: 'pct'; week: 4; min: 0.70; max: 0.75 }      // «70–75% от Н4»
  | { kind: 'conditional'; ... }                        // жим на наклонной, неделя 4: 75 lb при 70×10 во всех 4 подходах на Н3, иначе 70 lb × 10–12

interface Prescription { sets: number; repsMin: number; repsMax: number; weight: WeightRule; dropset?: boolean }
interface ProgramExercise { exerciseId: string; warmup: string; byWeek: [Prescription ×5] }
interface DayTemplate { type: 'A'|'B'|'C'; title: string; exercises: ProgramExercise[] }
```

Расписание: 35 дней цикла; тренировочные дни 1,3,5 / 8,10,12 / 15,17,19 / 22,24,26 / 29,31,33 → неделя = ⌈день/7⌉, тип = A/B/C по порядку внутри недели.

## 5. Расчёт весов (`weights.ts`)

Вход: предписание, id упражнения, номер недели, журнал текущего цикла, ручные стартовые веса.
Выход: `{ lb: number | null, hint?: string, source: 'program' | 'anchor' | 'heldBack' | 'manual' | 'unknown' }`.

1. **Якорь Н(k)** для упражнения = мода весов **выполненных рабочих подходов** этого упражнения на неделе k текущего цикла (при равенстве — больший вес).
   Н1: если на неделе 1 записей нет → мода недели 2 (на неделе 2 вес = Н1) → `startWeights` цикла → `null`.
   Если на неделе 2 вес был удержан правилом недобора — это всё равно вес Н1, так что правило не мешает.
2. **`fixed` / `added` / `plates`** — вес из программы.
3. **`pick`** — предлагается последний записанный вес упражнения, если есть, иначе `null` («подбери вес»).
4. **`anchor`** — Н(k) + delta, округлено к шагу упражнения. Если Н(k) неизвестен → `null`, подсказка «введи вес Н1».
5. **`pct`** — Н4 × 0,725, округлено к шагу; если Н4 неизвестен → `null`.
6. **Правило недобора** (недели 2–4): если на предыдущей неделе в любом рабочем подходе этого упражнения сделано на ≥2 повторения меньше `repsMin`, а программа на этой неделе даёт **больший** вес, чем фактический вес прошлой недели, → вес прошлой недели, `source: 'heldBack'`, подсказка «Вес не повышен: на прошлой неделе недобор повторений».
7. **Условие недели 4** для жима на наклонной: 75 lb, если на неделе 3 все 4 подхода ≥10 повторений с весом ≥70 lb; иначе 70 lb и 10–12 повторений.
8. В поле ввода подставляется: факт этого подхода (если уже записан) → вес предыдущего подхода этой тренировки, если он был изменён пользователем → расчётный вес.

Вес подходов «added» показывается как «+10 lb», «plates» — как «2×45 +20 / стор.»; в журнал пишется число: для `added` — добавочный вес, для `plates` — сумма на одну сторону.

## 6. Циклы (`cycle.ts`)

- Журнал хранит номер цикла. Якоря считаются только по текущему циклу.
- У каждого цикла есть настройки `CycleConfig = { offsets: Record<exerciseId, lb>, startWeights: Record<exerciseId, lb> }`:
  - `offsets` прибавляются ко всем весам `fixed` / `added` / `plates` (для `plates` — к стороне) этого упражнения во всех неделях цикла;
  - `startWeights` — Н1 для упражнений с `pick` (используется, если на неделях 1–2 нет записей).
  Цикл 1: всё пусто.
- После завершения дня 33 приложение показывает диалог «С каких весов начать новый цикл?»:
  - **(а) Как в программе.** offset += (вес недели 2 − вес недели 1 по программе) для каждого фиксированного упражнения; startWeight для `pick` = Н3 прошлого цикла.
  - **(б) Лучшие результаты.** Как (а), плюс для фиксированных упражнений offset += max(0, факт Н4 − расчётный вес недели 4); startWeight для `pick` = Н4 прошлого цикла (если есть, иначе Н3).
- Новый цикл начинается с дня 1. До завершения дня 33 диалог не показывается; его можно вызвать из профиля.

## 7. Данные (Dexie)

```
workouts: ++id, cycle, day, startedAt, finishedAt?
sets:     ++id, workoutId, [workoutId+exerciseId], exerciseId, kind('warmup'|'work'), index, lb, reps, dropReps?, doneAt
settings: key  → 'position' = { cycle, day }; 'cycle:<n>' = CycleConfig
```

- Подход пишется в БД при нажатии галочки; повторное нажатие — правка.
- «Следующая тренировка» = день из `settings.position`; при завершении тренировки позиция двигается на следующий тренировочный день.
- Пользователь может вручную выбрать другую тренировку/день в профиле («Где я в программе»).
- Экспорт: JSON `{ version: 1, exportedAt, workouts, sets, settings }`; импорт заменяет все данные после подтверждения.
- Первый запуск: позиция `{ cycle: 1, day: 12 }`.

## 8. Экраны

Тёмная тема, акцент жёлтый, крупные элементы под палец; нижняя панель вкладок: Тренировка · Прогресс · Питание · Профиль.

**Тренировка** (по макету):
- Заголовок «Тренировка», подзаголовок «День 12 · С: грудь, спина…», неделя и запас повторений (RIR).
- Кнопка «Начать» → секундомер тренировки в шапке.
- Список упражнений карточками; активная раскрыта: картинка (3 кадра от пользователя, нарезка CSS; или 2 кадра из free-exercise-db), мышцы, разминка (чипы), строки рабочих подходов: номер, вес (lb) со стрелками ±шаг, повторы со стрелками ±1, кнопка ✓.
- В последнем подходе упражнения с дропсетом — доп. поле «дроп, повт.».
- Подсказки правил (недобор, «введи вес Н1», условие недели 4) — под заголовком упражнения.
- Таймер отдыха: круг с обратным отсчётом, считается от времени старта (переживает блокировку экрана), пауза/сброс, короткий звук по окончании, если приложение на экране.
- Кнопка «Завершить тренировку» → сохраняет `finishedAt`, двигает позицию, показывает итог (время, подходы, тоннаж).

**Прогресс**:
- Переключатель Неделя / Месяц / Год.
- Плитки: тренировки, время, общий тоннаж (Σ lb × повт. рабочих подходов, для `added` — не учитываем, для `plates` — ×2 стороны).
- Выбор упражнения → линейный график рабочего веса (мода по тренировке) по датам.

**Профиль**: «Где я в программе» (цикл/день), «Стартовые веса» (19 упражнений с подбором), экспорт/импорт, версия.

**Питание**: заглушка «Скоро».

## 9. Ошибки и граничные случаи

- Нет данных для расчёта → поле пустое с подсказкой, ввод вручную.
- Незавершённая тренировка при перезапуске → продолжается с сохранёнными подходами.
- Импорт битого файла → сообщение об ошибке, данные не трогаются.
- `navigator.storage.persist()` запрашивается при старте, чтобы iOS не очищал данные.

## 10. Тестирование

- Vitest на `src/program/*`: расписание, якоря, каждый тип правила веса, правило недобора, условие недели 4, округление, разгрузка, цикл; плюс проверка данных программы (число подходов: A=36, B=38, C=35; разгрузка 22/23/21).
- Ручная проверка в браузере (мобильный вид): пройти тренировку, проверить сохранение после перезагрузки, экспорт/импорт.
